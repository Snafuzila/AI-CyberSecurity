# Project Status & Handover Summary

- **Objective:** Systematic comparison of Isolation Forest (IF) vs. Autoencoder (AE) for anomaly detection, enhanced with XAI (Explainability) and RAI (Responsible AI) layers, feeding into an LLM-based SOC orchestrator.
- **Dataset:** NSL-KDD only (`data/KDDTrain+.txt`, `data/KDDTest+.txt`). `data/credit_card_fraud_10k.csv` is present but **not yet wired in** — its schema (`transaction_id`, `merchant_category`, `is_fraud`, ...) doesn't match what `data_pipeline.load_credit_card_fraud()` expects (Kaggle's `Time`/`V1-V28`/`Amount`/`Class`); it would need its own loader.
- **Architecture:** Offline, standalone research suite at `research/xai_rai_comparison/`, fully decoupled from the live Kafka SOC pipeline (`agent_orchestrator.py`, `morpheus_lite_detector.py`) — no imports between them. The suite doesn't call any real LLM; it builds and prints the exact prompt text that would be sent to one.

## Phase-by-phase (matches the actual filenames)

- **Phase 1 — `train_and_persist.py`:** Trains `IsolationForestModel` and `AutoencoderModel` (plain PyTorch, not Keras) on NSL-KDD and persists everything Phase 2 needs to `artifacts/nsl_kdd/`: `isolation_forest.pkl`, `autoencoder.pt` (state_dict), `scaler.pkl`, `encoder.pkl`, and `manifest.json` (feature names, per-model thresholds, and precomputed global RAI metrics). Both models reached similar statistical performance: **IF F1 = 0.901, AE F1 = 0.907**.
- **Phase 2 — `enriched_payload.py`:** `generate_enriched_payload(event, event_id)` turns one raw event into an IF payload and an AE payload. XAI evidence: SHAP `TreeExplainer` top-3 signed feature contributions for IF; top-3 features by per-feature reconstruction error `(x - reconstruction)²` for AE. Each payload also carries the model's precomputed `rai_metadata` (precision, recall, f1, false_positive_rate, fairness_gap) read from the Phase 1 manifest.
- **Phase 3 — `llm_orchestrator.py`:** `rai_policy_evaluator()` turns `rai_metadata` into a containment decision (thresholds: FPR > 10% or fairness_gap > 10% → deny automated containment, require human approval). `build_llm_prompt()` formats the payload + decision into the final prompt text.
- **Phase 4 — `run_scenarios.py`:** Scans real NSL-KDD test predictions for one event matching each of 4 scenarios (`both_alert`, `if_only`, `ae_only`, `both_normal`), runs each through Phases 2–3, and prints both models' prompts per scenario.

## Key discovery: the ICMP fairness gap

The RAI layer caught something the accuracy metrics alone hid. Despite near-identical F1 scores, subgroup false-positive rates by `protocol_type` diverge sharply for Isolation Forest:

| Protocol | Count | Recall | False Positive Rate |
|---|---:|---:|---:|
| tcp | 36,509 | 92.2% | 7.3% |
| icmp | 2,809 | 92.8% | **54.9%** |
| udp | 5,238 | 46.7% | 12.5% |

IF's FPR gap (54.9% − 7.3% = **47.6 points**) exceeds the 10% policy threshold → **DENIED, human approval required.** AE's fairness gap (**7.2%**) stays under threshold → **ALLOWED, logged for audit.** (UDP's low recall, 46.7% vs ~92% elsewhere, is a second, separate disparity worth investigating alongside the ICMP one.)

**Caveat carried over from the original design:** `protocol_type` is a proxy attribute, not a protected/demographic class — this is a subgroup performance-disparity check, not a legal fairness audit.

## What's implemented vs. available-but-not-wired-in

- **Implemented and used in the Phase 1–4 payloads:** Precision, Recall, F1, False Positive Rate, Fairness Gap (max subgroup FPR difference).
- **Exists in `rai_analysis.py` but not yet used by Phases 1–4:** `robustness_report()` (noise-perturbation stability) and `transparency_report()` (SHAP concentration/Gini). These were used in the earlier `run_comparison.py` (NSL-KDD vs Credit Card Fraud) study, not in the LLM-payload pipeline — a reasonable Phase 5 addition if you want the LLM prompts to also reason about robustness/transparency, not just accuracy and fairness.

## Not part of the Phase 1–4 build — flagging so it isn't misattributed

Two files sit in `research/xai_rai_comparison/` that were **not** produced by this pipeline:
- `is_and_ae_on_nsl_kdd.py` — a Colab-exported script (Keras/torch-backend, uses `kagglehub`), a separate independent experiment.
- `nsl_kdd_test_predictions_from_saved_models.csv` — a full test-set prediction export (22,544 rows: `if_score`/`if_pred`/`ae_score`/`ae_pred`/`models_agree`), origin unclear — possibly generated by the Colab script above.

Both are real, worth keeping, but distinct from — and use a different AE framework than — the Phase 1–4 pipeline described above.
